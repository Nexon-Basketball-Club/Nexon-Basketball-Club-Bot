# 넥슨농구동호회 회비 봇

카카오톡 단톡방에서 회원이 **자기 회원 여부·회비·게스트비 미납을 직접 확인**하는 봇.
[메신저봇R](https://github.com/1-Byte/android-messengerbot)에서 돌고,
[NBC 백엔드](https://github.com/Nexon-Basketball-Club/Nexon-Basketball-Club)의
`/api/bot/*`를 호출한다.

운영진이 아무리 장부를 맞춰도 회원이 그걸 못 보면 소용이 없다는 게 이 봇의 출발점이다.

## 명령어

| 명령어 | 하는 일 |
|---|---|
| `!참석` | 참석 신청 (선착순). 정원이 차면 대기 순번을 받는다 |
| `!취소` | 참석 취소. 확정자가 빠지면 대기 1번이 자동 승계된다 |
| `!회비 <이름>` | 이번 분기 회원 여부 + 회비 + 게스트비 미납 |
| `!게스트비 <이름>` | 게스트비 미납만 (가장 오래된 건 날짜 포함) |
| `!미납` | 게스트비 미납자 전원, 금액 큰 순 |
| `!도움말` | 사용법 |

`!회비`를 이름 없이 치면 사용법이 나온다. 모르는 `!명령어`엔 아무 응답도 하지 않는다.

```
아무나: !회비 원동현

[봇] 원동현 님
    2026 Q3 회원 ✅
    회비 납부완료
    게스트비 미납 2건 · 30,000원
```

## 설계 메모

읽고 나서 고치라고 적어둔다. 그냥 그렇게 된 게 아니라 골라서 그렇게 된 것들이다.

- **참석 투표만 표시명(`sender`)을 쓴다.** 나머지는 아래 규칙대로 이름을 받는다.
  선착순 신청은 반대여야 하기 때문이다 — `!참석 원동현`은 `!참석`보다 느리고,
  **선착순에서 타이핑 길이가 곧 순위다.** 그리고 sender로만 넣고 sender로만 지우므로
  "자기 것만 취소"가 규칙이 아니라 결과로 성립한다. 남의 자리를 빼려면 표시명을 그
  사람으로 바꿔야 하는데 단톡방에서 그건 즉시 들킨다.
- **취소 답장에 승계를 같이 싣는다.** 봇은 먼저 말을 걸 수 없어서(알림 리플라이 토큰)
  "대기 1번이 확정됐습니다"를 알릴 수 있는 자리가 그 답장뿐이다. 단톡방에 뜨므로
  승계된 사람이 본다. 이 줄을 빼면 대기자는 자기 차례가 온 걸 영영 모른다.
- **`config.json`의 `pollRoom`에 적힌 방에서만 투표를 받는다.** 메신저봇R의 디버그
  채팅방에서 `!참석`을 치면 진짜 투표에 들어가기 때문이다. 조회 명령어일 땐 무해했지만
  쓰기라서 다르다. 안 적으면 아무 방에서나 받는다.
- **이름은 (참석/취소를 뺀) 나머지에서 항상 파라미터로 받는다.** 카톡 표시명(`sender`)은
  쓰지 않는다. 사람들이
  "동현아빠" 같은 닉네임을 쓰기 때문에 표시명으로 찾으면 상당수가 첫 시도에서 실패한다.
- **그래서 누구나 누구든 조회할 수 있다.** 표시명으로 본인 확인을 하는 건 이름만 바꾸면
  뚫리므로 보안이 아니라 불편만 만든다. 대신 노출 수위를 낮췄다.
- **회비는 금액을 안 낸다.** 분기 정액이라 회원이 이미 알고 있다.
- **게스트비는 금액을 낸다.** 건마다 다르고, 그 금액을 모르면 입금 자체를 못 한다.
- **회원이면 "납부완료"다.** 이 도메인에 "회비 미납"이라는 상태가 없다 — 회비는 걷는 게
  아니라 내고 싶은 사람이 내고, 낸 사실이 곧 그 분기 회원권이다. 안 낸 사람은 독촉
  대상이 아니라 그냥 그 분기 회원이 아니다.
- **게스트비 미납은 기간을 안 자른다.** 미납이면 언젠가 받을 돈이다. 기간으로 자르면
  봇은 "미납 없음"이라는데 장부엔 남아있는 모순이 생긴다.
- **동명이인은 되묻지 않고 전부 보여준다.** 조회가 어차피 공개라 숨길 게 없고, 왕복이
  줄어든다. 덤으로 중복 등록된 회원이 드러나 총무가 정리하게 된다.
- **문구는 봇이 만든다.** 서버는 JSON만 준다. 그래서 문구를 고치려면 태블릿에서
  `git pull` + 메신저봇R 재시작이 필요하다.

## 설치

1. 메신저봇R에서 봇 폴더를 만든다 → `/sdcard/msgbot/Bots/nbcdues/`
2. 그 폴더에 이 저장소를 clone한다. **저장소 루트가 곧 봇 폴더**여야 `bot.json`이 인식된다.
   ```
   cd /sdcard/msgbot/Bots/nbcdues
   git clone https://github.com/Nexon-Basketball-Club/Nexon-Basketball-Club-Bot.git .
   ```
3. `config.json.example`을 `config.json`으로 복사하고 값을 채운다.
   ```json
   {
     "serverUrl": "https://<railway-주소>",
     "botToken": "<서버 BOT_TOKEN과 같은 값>",
     "timeout": 5000
   }
   ```
4. 메신저봇R에서 봇을 켠다.

`config.json`은 **커밋하지 않는다** (`.gitignore`에 있다). 토큰이 들어있고, 이 저장소는
태블릿이 pull하는 곳이다.

### 서버 쪽

Railway 환경변수에 `BOT_TOKEN`을 같은 값으로 넣는다. 서버에 이 값이 없으면 봇 API는
401이 아니라 **500으로 죽는다** — 환경변수를 깜빡한 배포가 조용히 무인증으로 열리는 것보다
봇이 안 되는 편이 낫기 때문이다.

## 반응이 없을 때

**`!핑`이 어디가 막혔는지 알려준다.** 봇 → 설정 → 서버 → 토큰 → DB 순으로 짚는다.

```
봇 ✅
설정 ✅
서버 ✅
토큰 ✅
DB ✅
```

막힌 지점에서 멈추고 이유를 말한다:

| 출력 | 볼 곳 |
|---|---|
| `설정 ❌` | `config.json` — 뒤에 이유가 붙는다 |
| `서버 ❌` | serverUrl, 네트워크, Railway가 떠 있는지 |
| `토큰 ❌` | `config.json`의 `botToken`과 서버 `BOT_TOKEN`이 다르다 |
| `DB ❌` | 서버는 살아있는데 DB가 안 붙는다. Railway DB를 본다 |

주소와 토큰은 **일부러 안 찍는다.** 단톡방에 뜨는 답장이기 때문이다. 자세한 건 로그에 있다.

**`!핑`에 아무 답도 없다면** 메시지가 스크립트까지 도달을 못 하는 것이고, 스크립트를
고쳐봐야 소용없다. 확인할 것:

1. 메신저봇R에서 봇이 **켜져 있는지** (전원 토글)
2. 앱에 **알림 접근 권한**이 있는지 — 이게 없으면 메시지를 아예 못 본다
3. **봇 계정이 그 대화방에 있는지.** 태블릿의 카카오톡 계정이 그 단톡방 멤버여야 한다
4. 그 방의 카카오톡 **알림이 꺼져 있지 않은지.** 메신저봇R은 알림으로 메시지를 읽는다

### 겪었던 것들

**알림 접근 권한이 켜져 있는데도 메시지가 안 온다** — 설정상 ON이어도 Android가 리스너
연결을 끊어놓는 일이 있다. **껐다가 다시 켜면** 재연결된다. "확인"만으로는 안 잡히고
실제로 토글해야 한다. 컴파일과 `loaded` 로그는 멀쩡히 되기 때문에 스크립트 문제로
착각하기 쉽다.

**`Unable to resolve host "https"`** — `config.json`의 `serverUrl`에 `https://`가 두 번
들어간 것이다. `java.net.URL`이 호스트를 문자열 `"https"`로 읽는다. 지금은 `!핑`이
먼저 잡아준다.

**메신저봇R의 디버그 채팅방**에서는 알림을 거치지 않으므로, 거기서 되고 실제 방에서
안 되면 원인은 100% 알림 쪽이다. 스크립트를 고칠 필요가 없다는 걸 바로 알 수 있어서
가장 먼저 해볼 만하다.

### 로그

`Log.d()` / `Log.e()` 출력은 메신저봇R 앱의 **로그 화면**에서 본다 (봇 편집기의 로그 탭,
또는 앱 메뉴의 전역 로그).

메시지를 받을 때마다 이 줄이 찍힌다 — **`!` 필터보다 먼저** 찍으므로, 아무 메시지나
쳤을 때 이게 안 나오면 위 1~4번이 원인이다.

```
[nbcdues] recv room=넥슨농구 len=4
[nbcdues] cmd=도움말
[nbcdues] replied 87 chars
```

대화 본문은 안 찍는다. 단톡방 대화 전체가 태블릿 로그에 쌓이면 곤란하기 때문이다.
전부 보려면 `config.json`에 넣는다:

```json
{ "debug": true }
```

## 갱신

태블릿에서 `git pull` 후 메신저봇R 재시작.

문구나 명령어를 바꿀 때만 필요하다. 조회 로직·판정 기준은 서버에 있으므로 그쪽 변경은
Railway 배포만으로 반영된다.

## 제약

- Rhino 엔진(`useBabel: false`)이라 **템플릿 리터럴을 쓰지 않는다.** 문자열은 전부 `+`로
  잇는다. 이전 봇에서 실제로 이것 때문에 컴파일 에러가 났었다.
- 알림 리플라이 토큰 방식이라 봇이 **먼저 말을 걸 수 없다.** 받은 자리에만 답한다.
